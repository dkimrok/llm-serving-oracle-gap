## 1. 연구 질문과 기여

**RQ1 (총 갭).** 공개 프로덕션 트레이스에서, 완전정보 사후최적 스케줄(오라클) 대비 현행 휴리스틱 스케줄러의 성능 손실은 얼마인가?

**RQ2 (갭 분해).** 총 갭 중 (i) 출력 길이를 모르는 데서 오는 **정보 갭**과 (ii) 정책이 서툰 데서 오는 **알고리즘 갭**의 비중은?

**RQ3 (조건부 구조).** 갭은 워크로드 특성(부하율, 길이 변동계수, SLO 엄격도, 캐시 여유)의 함수로 어떻게 변하는가?

**기여 주장(4p 버전):**
1. LLM continuous batching 스케줄링의 사후최적을 계산하는 시간버킷 MILP 정식화 + 공개 구현
2. 정보 갭/알고리즘 갭 분해 프레임 — "예측기 연구 vs 정책 연구"의 한계효용 비교라는 실무 처방
3. 워크로드 특성 → 갭 크기의 회귀 지도 (cluster-robust)

**비기여(경계 명시):** 커널 효율(FlashAttention류), 모델 압축/양자화, 멀티노드 라우팅·오토스케일링은 범위 밖. 단일 인스턴스 스케줄링 결정의 품질만 측정.

## 2. 시스템 모델과 가정

- 단일 GPU 인스턴스, 단일 모델, continuous batching (vLLM 계열 의미론).
- 요청 i: 도착 시각 a_i, 프롬프트 길이 p_i (도착 시 관측), 출력 길이 L_i (완료 시까지 미지; 트레이스에는 기록됨).
- KV 캐시 용량 M (토큰 단위). 활성 요청 i의 시점 t 캐시 점유 = p_i + (지금까지 생성한 토큰 수).
- 반복(iteration)당 토큰 처리 예산 B: 한 반복에서 처리 가능한 총 토큰(프리필 청크 + 디코드 토큰 합) 상한. 반복 시간은 처리 토큰의 선형 함수 τ = α + β·(tokens) 로 근사(문헌 계수 + 민감도 분석). **v0.1 단순화:** 반복 시간을 상수로 두고 목적함수를 반복 수 단위로 계산, τ 모델은 민감도 분석에서만.
- 프리필 처리: 요청 승인 반복에 p_i 토큰을 예산 B에서 소비(청크드 프리필은 ⌈p_i/B_pf⌉ 반복으로 확장 가능 — v0.2 옵션).
- **오라클은 선점(preemption) 금지** (승인 후 완료까지 연속 점유). 이유: (a) 정식화 단순화, (b) 선점 허용 최적해 ≥ 선점 금지 최적해이므로 측정된 갭이 참 갭의 **하한** → 보수적 방향으로 방법론적 안전. 논문에 명시.
- 휴리스틱 시뮬레이션은 선점 허용(실제 vLLM 동작 반영) — 오라클 쪽만 보수적.

## 3. 오라클 MILP 정식화 (시간버킷)

**이산화.** 반복을 크기 Δ의 버킷으로 묶어 t = 1..T. (Δ는 충실도-확장성 손잡이; 기본 Δ = 8 iterations, 민감도 {4, 8, 16}.)

**결정변수.**
- z_{i,t} ∈ {0,1}: 요청 i가 버킷 t에 **승인**됨 (Σ_t z_{i,t} = 1, t ≥ a_i 버킷)
- x_{i,t} ∈ {0,1}: 요청 i가 버킷 t에 활성 (파생: 승인 버킷부터 d_i = ⌈L_i/Δ⌉ 버킷 연속 1 — 선점 금지이므로 x는 z로부터 선형 제약으로 유도)

**제약.**
- (연속성) x_{i,t} = Σ_{s ≤ t, s > t - d_i} z_{i,s}
- (캐시) Σ_i x_{i,t} · [p_i + g_i(t)] ≤ M, ∀t — 여기서 g_i(t) = 승인 후 경과 버킷 수 × Δ (생성 토큰). g_i(t)는 z와 선형 결합으로 표현: Σ_s z_{i,s}·min(Δ·(t-s+1), L_i). 계수는 전처리로 상수화 → 제약은 z에 선형.
- (토큰 예산) 버킷 t 처리량: Σ_i z_{i,t}·p_i (프리필) + Σ_i x_{i,t}·Δ (디코드) ≤ B·Δ
- (완료) C_i = 승인버킷 + d_i (z로부터 선형)

**목적함수 (두 버전 모두 실행).**
- (F1) 평균 지연: min Σ_i (C_i − a_i)
- (F2) SLO goodput: max Σ_i y_i, y_i ∈ {0,1}, y_i = 1 ⇒ TTFT_i ≤ θ_1 ∧ 평균 TBT_i ≤ θ_2 (버킷 단위 근사; big-M 없이 y_i가 z 선택지를 제한하는 형태로)

**규모 추정.** 슬라이스 n = 300–500 요청, T ≈ 600–1,500 버킷 → z 이진변수 ~수십만. 완화책: (a) 승인 가능 창 제한(도착 후 W 버킷 이내 승인 가정 — W 민감도), (b) rolling-horizon (창 H, 겹침 H/2), (c) MIP gap 1% 허용 + 시간제한, LP 완화 하한 병행 보고. **오라클 값은 [LP 하한, 발견해] 구간으로 보고** — 갭 추정의 불확실성을 정직하게 전달.

### 3.1 청크드 프리필 (v0.2, D3 확정)

**동기.** 실 트레이스의 p99 프롬프트(6.7k–7.7k 토큰)가 현실적 버킷 예산(~4k)을 초과 → v0.1의 "프리필 단일버킷" 가정 하에서 해당 요청은 영구 승인 불가. 청크드 프리필이 필수.

**설계 선택: 고정 청크.** 프리필을 요청당 버킷당 B_pf 토큰씩 결정론적으로 진행 (유연 청크는 선행제약 이진변수+big-M 필요로 기각). π_i = ⌈p_i/B_pf⌉, w_i = π_i + d_i. 승인 버킷 s, 경과 φ = t−s:

- 프리필 구간 φ ∈ [0, π_i): 토큰 소비 min(B_pf, p_i − φ·B_pf), 캐시 점유 min((φ+1)·B_pf, p_i)
- 디코드 구간 φ ∈ [π_i, w_i): 토큰 소비 min(Δ, L_i − (φ−π_i)·Δ), 캐시 점유 p_i + min((φ−π_i+1)·Δ, L_i)

완료 C_i = s + w_i, **TTFT_i = s + π_i − a_i** (프리필 종료 = 첫 토큰; F2가 자연 정의됨).

**성질.** (1) 모든 계수가 z만의 선형식으로 사전계산 → 모델 구조·크기 v0.1과 동일. (2) 고정 청크 오라클은 유연 청크 시스템의 제한 → 측정 갭은 참 갭의 하한 (선점 금지에 이은 보수성 2호; 논문 한계 절에 명시). (3) 휴리스틱 시뮬레이터도 동일 계수 함수 사용 → 오라클·휴리스틱이 같은 실행가능영역 공유, 갭 부호 보장. (4) B_pf ∈ {1024, 2048, 4096} 민감도 축 추가.

## 4. 3층 오라클 설계 (갭 분해의 조작화)

| 층 | 정보 | 계산 | 해석 |
|---|---|---|---|
| **A. O-true** | L_i 참값 | §3 MILP | 완전정보 상한 |
| **B. O-pred** | L̂_i 예측값 | L̂로 MILP 계획 → 시뮬레이터에서 참 L_i로 실행, 초과 시 수리 규칙(초과분 계속 점유, 캐시 위반 시 후속 승인 지연) | 현실적 정보 하 최적화 기계의 성능 |
| **C. 휴리스틱** | 정책별 상이 | 시뮬레이터 재생 | 현행 실무 |

- **정보 갭 ≈ A − B** (같은 최적화 기계, 정보만 차이)
- **알고리즘 갭 ≈ B − C_best** (유사 정보, 기계만 차이)
- 예측기: 1차로 (i) 조건부 중앙값(프롬프트 길이 구간별), (ii) 단순 회귀. 예측기 품질 자체를 축으로 한 민감도(oracle→noisy→marginal mean) 포함 — "정보 갭 곡선".
- **한계 명시:** B는 분포 정보 하 진짜 최적(다단계 확률계획)이 아니라 확정적 계획+수리이므로 정보 갭의 근사. 소규모 인스턴스에서 SAA(시나리오 30개) 확률계획과 비교해 근사 오차를 부록에 보고 (v0.2, 시간 남을 때만).

**휴리스틱 베이스라인 (C):**
1. FCFS + greedy admission (vLLM 기본 근사)
2. SJF-pred (예측 출력길이 오름차순)
3. SRPT-pred (잔여 예측길이, 선점 허용)
4. 보수적 승인 (캐시 여유 γ 확보 시만 승인) × {FCFS, SJF}
5. (여유 시) 학습형 1종 — 단순 정책 경사 or 문헌 재현 1개

- 이벤트 기반 재생 엔진 (Python, 단일 파일 목표): 입력 = 요청 스트림 + 정책, 출력 = 요청별 (승인, TTFT, 완료, 선점 횟수).
